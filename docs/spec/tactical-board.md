# 戦術ボード (Tactical Board) 仕様書・設計指針

## 1. 概要
フットボールの戦術図や連続的なフォーメーションの動きを作成・編集するためのメインキャンバス画面（Web: `/tactical`）およびキャプチャ作図基盤（Extension: Quick Canvas）の統一仕様書です。

---

## 2. 正式名称（共通語彙・ユビキタス言語）

指示や設計・実装において、画面要素および概念は以下の正式名称に統一します。

| 正式名称 | 指す対象・役割 |
|---|---|
| **1. トップバー (TopBar)** | 画面最上部のバー。プロジェクト一覧/タイトル、アスペクト比切替、チーム表示フィルタ（Both/Home/Away）、メンバー維持リセット、Undo/Redo、書き出し（Export）を配置。 |
| **2. ツールバー (Toolbar)** | メインキャンバス右上に配置される作図ツール選択バー（選択、直線、ツールバーコネクタ、矢印3種、ゾーン2種、テキスト、ピッチ固定、境界線表示、連続配置ロック、消しゴム等）。 |
| **3. メインキャンバス (MainCanvas)** | 中央の作図作業エリア全体。**大きさは常に不変**であり、その中央に選ばれたアスペクト比の「ピッチ枠」が配置される。ピッチ外側の余白も作業領域として利用できる。 |
| **4. ピッチ枠 (PitchFrame)** | メインキャンバス内に描画されるサッカーピッチの外枠。アスペクト比（`4:5`, `16:9`, `9:16`, `1:1`）に応じて形状と向きが変化する。 |
| **5. 境界線 / 境界線枠 (BoundaryBox)** | 静止画・動画の出力範囲を決める切り抜き枠。初期状態ではキャンバス上で非表示（内部データはデフォルト範囲を保持）。ツールバーで表示ONにした際、上部に表示される操作バーを **境界線オプション**（「全画面」「ピッチにフィット」）と呼ぶ。 |
| **6. オブジェクトオプション (ObjectOptions)** | 選手マーカー、矢印、ゾーン、テキスト、コネクタ等を1つ選択した際に対象物の近くに表示される操作メニュー（旧称: コンテキストHUD）。すべての属性変更はここで完結する。 |
| **7. ゴースト軌道 (GhostTrajectory)** | シーン2以降で、選択中またはドラッグ移動中の対象について、前シーンの初期位置（半透明マーカー/ボール）から現在位置へ伸びる点線矢印と曲線調整ハンドル。 |
| **8. 右パネル / ベンチキャンバス (RightPanel / BenchCanvas)** | 画面右側のパネル（`Formation` タブ / `Squad` タブの2タブ構成）。`Formation` タブでは対象チーム（Home/Away/Both）別のフォーメーション適性配置・チームカラー変更・マーカー表示切替および180度点対称の陣地反転（Swap）を行い、`Squad` タブ内の控え選手配置エリアを **ベンチキャンバス（サブキャンバス）** と呼んでメインキャンバスとドラッグ＆ドロップで選手を双方向移動できる。 |
| **9. タイムライン (TimelineBar)** | 画面最下部のバー。再生/一時停止ボタン、**シーンカード**一覧、シーン間トランジションコネクタ（移動時間表示＋設定ポップオーバー）、シーン追加ボタン、および全シーンの移動時間・静止時間・加減速をまとめて変更できる一括設定コントロールを配置。 |

## 3. 4大設計原則と不変条件（Architecture Invariants）

「どこかを直すと別の場所が壊れる」事象を根絶するため、ツールだけでなく全オブジェクト・パネル・タイムライン・座標/カメラ処理において以下の4原則を絶対条件とします。

### 原則1：単一真実源 ＆ 派生状態の二重保存禁止（Single Source of Truth）
- **1つのUI要素・1つの計算式・1つのデータ管理は、必ずコードベース内の1箇所にのみ存在する**構造とする。
- 実画面から参照されない旧コンポーネント群（旧 `panels/hud/`、旧 `panels/inspector/`、旧 `panels/slides/`、旧 `formation-sub-panel.tsx`、旧 `objects/` 内の重複ファイル等）は完全に削除する。
- **派生状態の保存禁止**: ストアに保存するデータは最小限の「正規化された生データ」のみとする。画面表示用の座標、カメラ投影後の位置、フィルタ後の選手リストなどを別 State や翻訳アダプターに二重コピーして保存することを禁止し、必ず純粋関数（Selector / Projection）でリアルタイムに算出する。

### 原則2：全要素の自己完結パッケージ化 ＋「頭脳（振る舞い）」と「見た目（Renderer）」の分離 ＋ 複合操作の単一トランザクション化
- **頭脳と見た目の完全分離**:
  - ツールに限らず、すべてのキャンバスオブジェクト（選手マーカー、ボール、矢印、ゾーン、テキスト、コネクタ）、右パネル（Formation / Squad）、タイムラインをそれぞれ独立したモジュールとして構成する。
  - 各モジュールは **「頭脳（状態更新・ドラッグ移動・選択・検証を担うロジック/Hook）」** と **「見た目（Konva描画・React UIのRenderer）」** を明確に分離し、UIコンポーネント内に直接の座標計算式や複雑な状態書き換えを書かない。
  - **選手マーカーの共通化**: 位置・ドラッグ移動・選択・オブジェクトオプション制御の「頭脳」と「マーカー下部の選手名ラベル表示」は1箇所で共通管理し、Web版の「2D丸マーカー」とExtension版の「3D足元リング」は見た目（Renderer）とホスト固有項目（背番号入力の有無、削除ボタンの有無）のみを差し替える。
- **複合操作の単一トランザクション化（Atomic Commands）**:
  - 「メンバー維持リセット」「アスペクト比切替」「フォーメーション適用」「Home/Away/Both一括変更」「ベンチ移動」などの複数データを同時に動かす操作は、ボタンの `onClick` 等に個別記述せず、ストア内の**1つの純粋コマンド関数**に集約する。どのUIから呼び出しても100%同じ処理を通ることで同期漏れバグを防ぐ。
- **ホスト別カタログ方式**:
  - Web版とExtension版のツールバー構成やオプションの違いは、コード内の `if` 分岐ではなく、起動時に注入するカタログ設定で宣言的に切り替える。

### 原則3：メインキャンバス不変 ＆ 将来のカメラ操作（チルト・左右覗き込み・パン・ズーム）を見据えた単一座標変換と5層レイヤー構造
現在は「カメラ正面・ピッチの傾き0°・ズーム1倍」で固定するが、すべての修正完了後に**「ピッチを縦に傾ける（チルト）」「カメラを左右から覗き込む（ヨー回転）」「パン・ズーム」**を追加実装してもバグが一切発生しないよう、現段階から以下の座標パイプラインとKonvaレイヤー構造を採用する。

1. **3段階の座標空間（Coordinate Spaces）と単一変換パイプライン（`CameraProjection`）**:
   - **① ピッチ論理座標（World / Pitch Space: `0〜100`）**:
     ストアに保存される唯一の永続化座標。アスペクト比変更や将来のカメラ操作（チルト・回転・ズーム）によって、ストア内の選手や矢印の論理座標データを書き換えてはならない。
   - **② キャンバス平面座標（Stage 2D Space: `px`）**:
     常に大きさが不変のメインキャンバス中央に配置される、選択アスペクト比の「ピッチ枠（`PitchRect`）」への基準2Dマッピング座標。
   - **③ スクリーン投影座標（Screen / Camera Space: `px` + `perspectiveScale`）**:
     カメラパラメータ `CameraState = { tilt, yaw, zoom, panX, panY }`（現在は初期値 `{ tilt: 0, yaw: 0, zoom: 1, panX: 0, panY: 0 }` 固定）を適用した最終描画座標および奥行きスケール。
   - **単一変換の原則**:
     - 静止画描画、アニメーション再生、エクスポート、オブジェクトオプションの表示位置算出は、すべて単一の正変換関数 **`worldToScreen(worldPos, pitchRect, camera)`** を参照する。
     - マウスクリック、ドラッグ移動、ベンチからのドロップ位置算出は、すべて単一の逆変換関数 **`screenToWorld(screenPos, pitchRect, camera)`** を参照する。

2. **カメラ・純粋描画に対応する 5層レイヤー構造（Konva Layers & Overlays）**:
   将来ピッチを傾けた際、「地面に張り付いて傾くもの」「地面の位置に追従しつつカメラ正面を向いて立つもの（ビルボード）」「カメラの傾きに依存せず画面正面に貼られるもの」が混在して壊れるのを防ぐため、以下の5層に分離する：
   - **Layer 1: `PitchGroundLayer`（地面・平面投影レイヤー）**:
     ピッチ背景・白線枠（`PitchFrame`）、地面に塗られるゾーン（`Zone`）、地面上を走る矢印・直線・コネクタ・ゴースト軌道のライン。将来カメラを傾けた際、地面の平面変形（パースペクティブ投影）をそのまま受ける層。
   - **Layer 2: `BillboardObjectLayer`（ビルボード・立ちオブジェクトレイヤー）**:
     選手マーカー（2D丸マーカー / 3D足元リング＋下部の選手名ラベル）、ボール、テキスト。
     足元の基準位置 `(x, y)` は `worldToScreen` で移動し奥行きに応じた遠近スケール（`perspectiveScale`）が掛かるが、**選手マーカーの円や文字自体は縦に潰れず常にカメラ正面（正円・読める文字）を向くビルボード方式**とする。また、カメラを傾けた際に手前の選手が奥の選手の前に重なるよう、スクリーンY座標（深さ）で描画順ソートを行える構造とする。
   - **Layer 3: `InteractionPreviewLayer`（作図プレビュー・編集補助レイヤー）**:
     作図中のプレビュー図形、範囲選択ボックス、選択ハイライト枠、ゴースト軌道の操作ハンドル、矢印・ゾーンの頂点・曲率ハンドル。
   - **Overlay 1: `ViewportCropOverlay`（画面基準の境界線枠レイヤー）**:
     境界線枠（`BoundaryBox`）と外側マスク。これは地面ではなく「カメラのレンズ枠（出力切り抜き枠）」であるため、将来ピッチを傾けたり左右から覗き込んだりしても境界線枠自体は傾かず、常に画面に対して水平・垂直な長方形として機能する。
   - **Overlay 2: `HtmlHudOverlay`（オブジェクトオプション・境界線オプション）**:
     選択中オブジェクトの `worldToScreen` スクリーン座標に追従して浮動表示される React UI メニュー。

### 原則4：境界線枠による出力一致 ＆ 再生・出力時の純粋描画（Clean Render）
- **出力範囲の不変条件**: 静止画（PNG）も動画（プレビュー再生・WebM/MP4出力）も、キャンバス上で境界線枠が表示中か非表示かに関わらず、常に内部で保持されている**「境界線枠（BoundaryBox）の領域」**がそのまま出力範囲となる（※GIF出力は廃止し、短尺アニメーションもすべてMP4/WebM動画として出力する）。
- **純粋描画の不変条件**: アニメーション再生中および画像・動画の出力時は、以下の**編集用補助表示（Layer 3 および Overlays）をすべて完全に非表示**にし、オブジェクト本来の見た目のみを描画する：
  - 選択状態の強調（ハイライト枠・リング）
  - オブジェクトオプション（メニューバー）
  - 境界線枠（破線枠・外側マスク）および境界線オプション
  - ゴースト軌道（半透明マーカー・点線矢印・曲線ハンドル）
  - 矢印の端点・曲率ハンドル、ゾーンの頂点・回転ハンドル

### 原則5：車輪の再発明（自前実装）の禁止と標準ライブラリへの完全委譲
複雑な計算やブラウザ互換処理を自前で手書きしてバグを生むことを防ぐため、各領域は以下の採用ライブラリに100%委譲し、旧来の自前実装・廃止パッケージは完全に撤去する：
- **アニメーション再生・イージング・将来のカメラ補間**: **`gsap` + `@gsap/react`**（`useGSAP` / `contextSafe` / `gsap.timeline()`）に統一する。自前の `requestAnimationFrame` ループ管理や自前イージング関数（`easing.ts`）は廃止する。将来のカメラ操作（チルト・左右回転・ズーム・リセット）の滑らかな遷移もすべて `useGSAP` で制御する。
- **キーボードショートカット**: **`react-hotkeys-hook`** に一元化する。自前の `window.addEventListener('keydown')` による修飾キー分岐（`use-keyboard-shortcuts.ts` / `canvas-shortcuts-handler.ts`）および旧 `hotkeys-js` は廃止する。
- **オブジェクトオプション（HUD）・ポップオーバーの位置自動調整**: **`@floating-ui/react`**（`flip()`, `shift()`, `offset()`）に委譲し、画面端での上下反転・左右クランプを自動化する（自前の固定値クランプ計算 `use-hud-position.ts` は廃止）。
- **カラーピッカーUI**: **`react-colorful`** を使用し、ポップオーバー内で完結する色変更UIに統一する（OS依存の `<input type="color">` 透明重ねハックは廃止）。
- **動画・静止画・ZIP出力**:
  - **動画（MP4 / WebM）**: **`mediabunny`** の高レベルAPI（`CanvasSource` 等）に委譲し、旧 `mp4-muxer` / `webm-muxer` および自前の WebCodecs `VideoEncoder` チャンク管理コードを廃止する。
  - **静止画（PNG）**: Konva 標準の **`stage.toBlob()`** を直接使用し、旧 `html-to-image` や自前の `dataUrlToBlob` 変換を廃止する（`gif.js` によるGIF出力も完全廃止）。
  - **ZIP圧縮**: 高速・軽量な **`fflate`** に統一し、旧 `jszip` を廃止する。

## 4. 機能別詳細仕様

### 4.1 メインキャンバス・アスペクト比・境界線枠
1. **アスペクト比とピッチの向き**:
   - 新規プロジェクト・初期状態のデフォルト比率は **`4:5`** とする。
   - **横向きピッチ**: `16:9` のみ。
   - **縦向きピッチ**: `4:5`、`9:16`、`1:1` の3種類。
2. **アスペクト比切替時の挙動**:
   - メインキャンバス全体の大きさは変わらず、中央のピッチ枠が選択した比率・向きに切り替わる。
   - すでに配置されている選手マーカー、ボール、矢印、ゾーンは、**ピッチ上の同じ相対位置（例：ペナルティスポット上、センターサークル中央）にそのまま留まる**よう自動変換される。
   - 選手マーカーやボールの見た目の大きさは、ピッチのサイズに対して自然に見える比率へ自動調整される。
3. **境界線枠（BoundaryBox）の内部初期状態とキャンバス上の非表示デフォルト**:
   - **内部データの初期状態**:
     - **Web版**: 初期状態（および比率変更・リセット時）は、内部的に**「ピッチ枠」にぴったり合わせた範囲**をデフォルトの境界線状態として保持する。
     - **Extension版**: 初期状態は、内部的に**「スクリーンショット（キャンバス全体＝100%）」に合わせた範囲**をデフォルトの境界線状態として保持する。
   - **キャンバス上の初期表示状態（デフォルト非表示）**:
     - 初期状態（およびリセット時）では、ツールバーの「境界線表示」は**非選択（OFF）状態**とし、**メインキャンバス上に境界線枠（破線枠・外側マスク）および境界線オプションは見えない状態**にする。
     - ユーザーがツールバーの「境界線表示」ボタンを押してONにした時のみ、キャンバス上に境界線枠と上部の **境界線オプション**（「全画面」「ピッチにフィット」の2ボタン）を表示し、枠の調整を行えるようにする。

### 4.2 ツールバー（右上）の構成
1. **Web版ツールバー**:
   - `選択`
   - `直線`
   - `ツールバーコネクタ（両端が○の線）`: 主に味方と相手のマンマーク・参照関係を表現するために使用する。
   - `実線矢印` / `破線矢印` / `波線矢印`
   - `矩形ゾーン` / `多角形ゾーン`
   - `テキスト`
   - `ピッチ固定（ロック）`
   - `境界線表示切替`（初期状態はOFF＝非表示）
   - `連続配置ロック`
   - `消しゴム`
   - ※Web版のツールバーには「2D選手マーカー配置ボタン」および「3D選手マーカー配置ボタン」は置かない（Web版の選手追加は右パネルの `Squad` タブから行う）。
2. **Extension版ツールバー**:
   - Web版共通の作図ツール群 ＋ **`3D選手マーカー（足元リング）`** を配置する。
   - ※Extension版には「2D選手マーカー」および「ピッチ固定」は置かない。

---

### 4.3 オブジェクトオプション（選択時メニュー）＆ マーカー下の名前表示
オブジェクトを1つ選択した際に対象の近くに表示し、ドラッグ移動開始と同時に非表示にする。画面端（上端・左右端）では見切れないよう自動で表示位置（上下反転・左右クランプ）を調整する。

1. **マーカー下部の選手名ラベル表示 ＆ 2D/3Dマーカーの中央表示仕様（Web 2D / Extension 3D）**:
   - Web版（2Dマーカー）で試合詳細からの遷移時や名前設定時にマーカーの下部に選手名が表示されるのと同様に、**Extension版（3Dマーカー）でも名前を追加・設定した際は、3Dマーカー（足元リング）の下部に選手名ラベルを表示する**。
   - **2D丸マーカー（`circle`）の内部表示（`insideContent`）**: `Num`（背番号）、`Photo`（`player_photos` テーブルの256×256 WebP顔写真を円内にクリップ描画。顔写真が未登録の選手は背番号表示にフォールバック）、`Empty`（円内は何も表示しない）の3モードに対応する。
   - **3D足元リング（`ring`）の内部表示**: 足元リングの中央には何も表示しない（背番号や顔写真をリング中央に描画することはなく、下部の選手名ラベルのみを表示する）。
2. **選手マーカー（Web版・2Dマーカー）のオブジェクトオプション**:
   - `視野（Vision Cone）`: 扇形の視野表示のON/OFF（向き・角度・長さをドラッグ操作可能）。
   - `コネクタ`: 主に味方同士の戦術的な繋がりを表現するラインの追加・解除。
   - `矢印3種（実線・破線・波線）`: その選手を起点とする矢印をワンクリックで追加。
   - `フォーカス（強調）`: スポットライト強調のON/OFF。
   - `ロック`: 誤操作防止の位置固定ON/OFF。
   - `選手情報変更ボタン`: ボタンを押すとミニフォーム（ポップオーバー）が開き、**`背番号`** と **`名前`** を変更できる。
   - `中の色変更` / `枠の色変更`: メインカラーと枠線カラーをカラーピッカーで変更。
   - `大きさ変更`: マーカーのスケール（`-` / `+`）を変更。
   - ※Web版では「削除」ボタンおよび「ベンチへ移動」ボタンは置かない（ベンチへの移動はドラッグ＆ドロップで行う）。
3. **選手マーカー（Extension版・3Dマーカー）のオブジェクトオプション**:
   - `視野` / `コネクタ` / `矢印3種` / `フォーカス` / `ロック`
   - `選手情報変更ボタン`: ボタンを押すと **`名前`** を変更できるフォームを開き、入力した名前を3Dマーカーの下部に表示する。
   - `色変更`: リングの色を変更。
   - `大きさ変更`: スケール（`-` / `+`）を変更。
   - `削除`: マーカーを削除するゴミ箱ボタン。
4. **その他のオブジェクト（矢印・ゾーン・テキスト・コネクタ・ボール）**:
   - **矢印 / 直線 / ツールバーコネクタ**: 色変更、太さ変更、線種切替（実線/破線/波線）、ロック、削除。
   - **コネクタ（選手間）**: 実線/点線切替、太さ変更、色変更、削除。
   - **ゾーン**: 色変更、枠線有無/スタイル、ロック、削除。
   - **テキスト**: テキスト再編集、文字サイズ変更、色変更、ロック、削除。

### 4.4 右パネル（Formation / Squad・ベンチキャンバス）・試合連携・リセット
右パネルは **`Formation`** と **`Squad`** の2タブ構成とする（旧 `Properties / Inspector` タブは廃止）。

1. **Formation タブ**:
   - **ピッチ展開モードのデフォルト**: `Half` / `Full` 切替のデフォルトは **`Full`**（フルピッチ配置）とする。
   - **対象チームセレクター（`Home | Away | Both`）**:
     - 旧来の `HOME | AWAY` 2択トグルおよび折りたたみ式の `Batch Player Display` セクションは廃止する。
     - 代わりに、トップバーと同様に **`Home | Away | Both` の3択ボタン** を上部に配置する。
     - ユーザーはこの `Home | Away | Both` のいずれかを選択した状態で、以下の3つの設定を直接（選択対象に対して一括で）変更できる：
       1. **チームカラー変更（色変更）**: 選択中の対象（Home / Away / Both）のチームカラーを変更する。
       2. **フォーメーション変更（プリセット選択）**: 選択中の対象（Homeのみ / Awayのみ / Both＝両チーム同時）にフォーメーションプリセットを適用し、ピッチ白線枠内の適切なポジション座標（GKはゴールライン直前）へ配置する。この際、**各選手の元のポジション情報（GK, CB, LB, RB, DM, CM, AM, LW, RW, CF 等）は上書きせず保持し、縦ラインと左右レーン（左・中央・右）の適性が一致する枠へ自動マッチングして配置する**。また、試合データ連携時（`matchFormations` 保持時）は、選択中のチーム（Home / Away）の試合フォーメーションがプリセット一覧上で選択状態として連動表示される。
       3. **マーカー内の表示変更**: 選択中の対象（Homeのみ / Awayのみ / Both＝両チーム全員）の選手マーカー内部の表示モード（`Num`［背番号］ / `Photo`［写真］ / `Empty`［空］）を一括変更する。
   - **陣地反転（Swap）**:
     - 実行すると、ピッチ上の選手マーカー（`area === 'pitch'`）、ボール、矢印、ゾーン、テキストをすべて**ピッチ中心 `(50, 50)` を基準に 180度点対称回転（`x' = 100 - x, y' = 100 - y`）**させる（左右のサイドバックやウイングの位置関係が鏡像で逆転しないよう、縦・横ともに反転する）。
     - **ベンチキャンバス上の控え選手（`area === 'bench'`）は反転対象外**とし、グリッド配置を維持する。
     - 反転状態（`isSidesSwapped`）はスライドごとに保持され、Swap 適用後にフォーメーションプリセットの再選択や「メンバー維持リセット」を行った場合も、反転後の陣地（Home が右/上陣地、Away が左/下陣地）を維持して配置する。

2. **Squad タブ ＆ ベンチキャンバス（サブキャンバス）**:
   - **Club & Season Presets（通常ボード専用）**:
     - 旧 Formation タブにあった `Club & Season Presets`（クラブ・シーズン別の選手プリセット読込機能）は **`Squad` タブへ移動**する。
     - この機能は**通常の戦術ボード（`matchId` なし）の時のみ表示・適用可能**とし、試合詳細経由の戦術ボード（`matchId` あり）では非表示とする。
   - **選手追加フォーム**: 背番号・ポジション・名前を入力して選手を追加できる。
   - **ベンチキャンバス（サブキャンバス）**:
     - 控え選手のマーカーが配置される領域。ベンチキャンバス内でもマーカーを自由にドラッグ移動できる。
     - **「整理」ボタン**: ベンチキャンバス内の選手をポジション順（GK / DF / MF / FW）のグリッドに綺麗に整列させる。
   - **メインキャンバス ⇄ ベンチキャンバスの双方向ドラッグ＆ドロップ（ボタン移動の廃止）**:
     - オブジェクトオプションやベンチリスト内の「ベンチ移動ボタン／ピッチ投入ボタン／交代ボタン」は廃止し、**メインキャンバス ⇄ ベンチキャンバスのドラッグ＆ドロップ操作に一本化**する。
     - ベンチキャンバスからメインキャンバスへ選手をドラッグ＆ドロップすると、ドロップした位置に投入される。
     - メインキャンバスからベンチキャンバスへ選手をドラッグ＆ドロップすると、ベンチキャンバスへ退避する。
     - **退避時のオプション自動初期化**: ベンチへ移動した選手は、`視野`・`フォーカス`・`コネクタ`・`起点矢印`・`ゴースト軌道` などの個別オプションがすべて自動的にクリアされる。

3. **試合詳細からの遷移連携（`/tactical?matchId=xxx`）と `New Project` 挙動**:
   - **自動配置（クラブ戦データ対象）**:
     - ダッシュボードや試合詳細から `matchId`（および任意の `minute`）付きで遷移した場合、Dexie DBから該当試合データを取得する（元の試合データは一切変更せず、戦術ボード上のデータとして展開する）。
     - 指定分数における `formation.formationSlots`（`1〜11`＝ピッチ上出場選手、`0`＝未出場控え選手）と `formation.formationPositions`（縦横スロット座標）および選手の `position` から、各チームのフォーメーションを戦術ボードで採用（選択状態に）し、11人の役割と左右の位置関係（LCB/RCB、LCM/RCM、LW/RW等）を正確に紐づけてメインキャンバスへ自動配置する（途中交代出場で元の `position` が `'Sub'` の選手には、割り当てられたフォーメーション枠のポジションを戦術ボード上で補完する）。
     - ベンチキャンバスには、**未出場の控え選手（`formationSlots === 0`）を先頭に、すでに交代で退いた先発選手をその後ろに**並べて自動配置する（交代前後のシーン作成に対応）。
     - ※代表戦データ（`NationalMatch`）はフォーメーション・ポジション・背番号・イベント座標データを持たないため自動配置のスコープ外とする。
   - **試合詳細経由ボードでの `New Project` 作成**:
     - 通常時（`matchId` なし）の `New Project` は汎用選手（1〜11番）の通常戦術ボードを作成する。
     - **試合詳細経由の戦術ボード（`matchId` あり）で `New Project` を実行した場合は、通常の汎用ボードには戻さず、その試合の出場・控えメンバーと各チームの試合フォーメーションを引き継いだ「試合詳細版の戦術ボード」として新規プロジェクトを作成する**。

4. **トップバーの「メンバー維持リセット」**:
   - 押下すると、**現在のスタメン・ベンチのメンバー構成（選手ID・名前・背番号・所属チーム）はそのまま維持**し、以下の初期化を行う：
     - **フォーメーション位置への再配置**:
       - **通常の戦術ボード（`matchId` なし）**: 初期フォーメーション位置（Home `4-2-3-1` / Away `4-4-2`、Fullモード）へ戻す。
       - **試合詳細経由の戦術ボード（`matchId` あり）**: **その試合における各チームの実際のフォーメーション**（試合データから取得・保持された Home / Away それぞれのフォーメーション）を採用して初期位置へ戻す。
     - ボールを中央 `(50, 50)` へ戻す。
     - 境界線枠の内部データを初期状態（Web版＝ピッチ枠フィット）へ戻し、キャンバス上の境界線表示をOFF（非表示）にする。
     - 矢印・ゾーン・テキストおよび選手個人のオプション（視野・フォーカス・コネクタ・ゴースト軌道）をすべて消去する。

## 5. タイムライン・ゴースト軌道・アニメーション再生
1. **シーン（スライド）管理**:
   - 下部タイムラインバーでシーンの追加（空シーン追加／現在シーンの複製追加）、ドラッグ＆ドロップ（`@dnd-kit`）による順序入れ替え、複製、削除を行える（最低1シーンは保護）。
   - **シーンカード内表示の整理**: カード本体には静止時間（例: `静止 0.5s`）と配置オブジェクト数（選手・矢印・ゾーン）のみを簡潔に表示し、移動時間はシーン間コネクタへ分離して視認性を確保。
   - **カード操作オーバーレイ（`SlideCardActions`）**: カードホバー時に表示される操作アイコン群（複製・削除・個別設定等）は、カード枠外ではなく枠内右上（`top-1 right-1`）に半透明背景オーバーレイとして収容し、タイムライン上端での見切れを防止。すべてのクリック・ポインター操作には `e.stopPropagation()` を適用し、DndKit のドラッグ開始やカード選択との干渉を防止。
2. **シーン間トランジションコネクタ ＆ 移動時間・静止時間・加減速設定**:
   - **シーン間トランジションコネクタ（`TransitionConnector`）**:
     - シーンカードとシーンカードの間に小型コネクタ要素を配置し、到着先シーンへの移動時間（秒）を「── 1.0s ──▶」形式で直感的に表示する。
     - コネクタをクリックすると、そのシーンのトランジション設定ポップオーバーが開く。
     - ※先頭シーン（Scene 1）の前にはコネクタを表示しない（先頭シーンは開始地点であり、到着移動時間が存在しないため）。
   - **個別シーン設定ポップオーバー（`SlideTransitionPopover`）**:
     - 各シーンカードの時間バッジクリック、ホバー設定アイコン、または右クリックメニュー「トランジション設定...」から開くことができる。
     - `@floating-ui/react` の **`FloatingPortal`**（`strategy: 'fixed'`）により親要素の横スクロール（`overflow-x-auto`）や CSS `transform` に拘束されず、常に画面最前面に欠けなく表示される。
     - 移動時間（0.1s〜10.0s、Scene 1 は無効表示）、静止時間（0.0s〜5.0s）、加減速（等速 `linear`、滑らか `ease-in-out`、加速 `ease-in`、減速 `ease-out`）を調整可能。
   - **全シーン一括設定ポップオーバー（`BatchTransitionPopover`）**:
     - タイムラインバー右側の「一括設定」ボタンから開き、全シーンの移動時間・静止時間・加減速をまとめて一度に変更できる。
     - 一括変更は単一の Undo 履歴（`updateAllSlideTransitions`）として記録され、1手のアンドゥ操作でプロジェクト内全スライドの設定が元通りに復元される。
   - **到着先シーン基準の総時間統一**:
     - 総再生時間計算（`calculateUnifiedTotalDuration`）および補間フレーム計算は到着先スライド基準に統一され、スライド1枚時は `0.0s`、2枚目以降はそのシーンへの移動時間＋静止時間の合計となり、再生コントロールの表示時間と実際の動画時間が 100% 一致する。
3. **ゴースト軌道（GhostTrajectory）の仕様**:
   - **表示条件**: シーン2以降で前のシーンから位置が移動した選手・ボールについて、**その選手（またはボール）が「選択状態」または「ドラッグ移動中」の時のみ**ゴースト軌道（前シーン位置の半透明表示＋点線矢印＋曲線ハンドル）を表示する。非選択時は表示しない。
   - **リアルタイム追従**: 選手やボールを**ドラッグし始めた瞬間（1ピクセル目）から**、ゴースト軌道の点線矢印の先端と曲線ハンドルが現在位置に遅れなくリアルタイム追従する。
   - **曲線調整**: ゴースト軌道の中央ハンドルをドラッグすることで移動ルートを曲線（ベジェ曲線）に曲げることができ、アニメーション再生時もその曲線ルート通りに動く。
4. **アニメーション再生**:
   - 下部タイムラインの再生ボタンまたはスペースキーで、シーン1から最終シーンまで連続再生する（再生ボタン横の旧リセットボタンは置かない）。
   - **GSAP タイムライン統括**: `gsap.timeline()` により再生・一時停止・シーク・位置同期を一元管理し、自前 rAF ループは全廃。コンポーネント破棄時や再生停止時には必ず `timeline.kill()` による RAII クリーンアップを徹底。
   - **再生中の純粋描画（Clean Render）**: 再生開始（`isPlaying || isExporting`）と同時に、選択枠・オブジェクトオプション・境界線枠・ゴースト軌道等の編集用UIをすべて隠し、選手・ボール・矢印・ゾーン・テキストの本来の見た目だけを滑らかにアニメーションさせる。
   - 再生完了後または一時停止時、すべてのマーカーとボールが消失・座標ズレを起こさず正確な位置に保たれる。
