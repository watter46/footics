# 戦術ボード (Tactical Board) 仕様書・設計指針

## 1. 概要
フットボールの戦術図や連続的なフォーメーションの動きを作成・編集するためのメインキャンバス画面（Web: `/tactical`）およびキャプチャ作図基盤（Extension: Quick Canvas）の統一仕様書です。
2D完全平面キャンバスによる正確な作図と、3Dカメラオービット・6大プリセットを備えたスプリットプレビューワークスペース、およびPowerPoint風のフェーズ（Phase）フォルダー構造による高度なシーケンス制作を統合しています。

---

## 2. 正式名称（共通語彙・ユビキタス言語）

指示や設計・実装において、画面要素および概念は以下の正式名称に統一します。

| 正式名称 | 指す対象・役割 |
|---|---|
| **1. トップバー (TopBar)** | 画面最上部のバー。戻るボタン、左シーケンスパネル切替、プロジェクト一覧/タイトル（インライン編集＋保存状態表示）、Undo/Redo、アスペクト比切替（4:5, 16:9, 9:16, 1:1）、チーム表示フィルタ（Both/Home/Away）、右パネル切替、3Dスプリットプレビュー切替（`Columns2`）、Copy PNGボタン、書き出し（Export）モーダル、および詳細メニュー（New Project、ピッチ画像設定、プリセット読込等）を配置。 |
| **2. ツールバー (Toolbar)** | メインキャンバス右上に配置される作図ツール選択バー（選択、直線、ルートルート線［Route Line］、矢印3種、矩形ゾーン、多角形ゾーン、テキスト、ピッチ固定、境界線表示、連続配置ロック、消しゴム等）。 |
| **3. メインキャンバス (MainCanvas)** | 中央の2D作図作業エリア全体。作業用のズーム・パンが可能な完全平面ビューポートであり、その中央に選ばれたアスペクト比の「ピッチ枠」が配置される。ピッチ外側の余白も作業領域として利用できる。 |
| **4. ピッチ枠 (PitchFrame)** | メインキャンバス内に描画されるサッカーピッチの外枠。アスペクト比（`4:5`, `16:9`, `9:16`, `1:1`）に応じて形状と向きが変化する。デフォルトでサイアン系ライン（`#38bdf8`）およびソリッド背景（`#0B303E`）または大理石テクスチャが描画される。 |
| **5. 境界線 / 境界線枠 (BoundaryBox)** | 静止画・動画の出力範囲を決める切り抜き枠。初期状態ではキャンバス上で非表示（内部データはデフォルト範囲を保持）。ツールバーで表示ONにした際、上部に表示される操作バーを **境界線オプション**（「全画面」「ピッチにフィット」）と呼ぶ。 |
| **6. オブジェクトオプション (ObjectOptions)** | 選手マーカー、矢印、ゾーン、テキスト、コネクタ等を1つ選択した際に対象物の近くに表示される操作メニュー（旧称: コンテキストHUD）。カラーピッカー（`react-colorful`）を含めすべての属性変更はここで完結する。 |
| **7. ゴースト軌道 (GhostTrajectory)** | シーン2以降で、選択中またはドラッグ移動中の対象について、前シーンの初期位置（半透明マーカー/ボール）から現在位置へ伸びる点線矢印と曲線調整ハンドル。 |
| **8. 左パネル / シーケンス一覧 (LeftPanel)** | 画面左側のパネル。PowerPoint風の「フェーズ（Phase）」フォルダーと各シーンカードが並び、各カードにはピッチ縮小描画（サムネイル）が表示される。フェーズの追加・削除・名称変更およびシーン追加・切り替えを行う。 |
| **9. 3Dスプリットプレビュー (SplitPreview)** | メインキャンバス右側に左右分割で開くリアルタイム3Dカメラ投影プレビュー。オービット（Tilt 0〜70°, Yaw 0〜360°）、パン、ズーム操作、6大カメラプリセットUI、再生コントロールを備え、高画質Canvas2Dにより選手写真付きで描画される。 |
| **10. 右パネル / ベンチキャンバス (RightPanel / BenchCanvas)** | 画面右側のパネル（`Formation` / `Squad` / `Pitch` の3タブ構成、48pxアイコンレールに折りたたみ可能）。`Formation` ではチーム別（Home/Away/Both）のフォーメーション適用・カラー変更・表示切替・180度陣地反転（Swap）を行い、`Squad` 内の控え選手配置エリアを **ベンチキャンバス（サブキャンバス）** と呼んでメインキャンバスとドラッグ＆ドロップで双方向移動できる。`Pitch` では背景（Solid/Marble）、オーバーレイ、ライン色・太さを調整する。 |
| **11. タイムライン (TimelineBar)** | 画面最下部のバー。再生/一時停止ボタン、アクティブなフェーズに属する**シーンカード**一覧、シーン間トランジションコネクタ（移動時間表示＋設定ポップオーバー）、シーン追加ボタン、および全シーン一括設定コントロールを配置。`Mod+M` でのシーン複製や横スクロールに対応。 |

## 3. 4大設計原則と不変条件（Architecture Invariants）

「どこかを直すと別の場所が壊れる」事象を根絶するため、ツールだけでなく全オブジェクト・パネル・タイムライン・座標/カメラ処理において以下の4原則を絶対条件とします。

### 原則1：単一真実源 ＆ 派生状態の二重保存禁止（Single Source of Truth）
- **1つのUI要素・1つの計算式・1つのデータ管理は、必ずコードベース内の1箇所にのみ存在する**構造とする。
- 実画面から参照されない旧コンポーネント群（旧 `panels/hud/`、旧 `panels/inspector/`、旧 `panels/slides/`、旧 `formation-sub-panel.tsx`、旧 `objects/` 内の重複ファイル等）は完全に削除する。
- **派生状態の保存禁止**: ストアに保存するデータは最小限の「正規化された生データ」のみとする。画面表示用の座標、カメラ投影後の位置、フィルタ後の選手リストなどを別 State や翻訳アダプターに二重コピーして保存することを禁止し、必ず純粋関数（Selector / Projection）でリアルタイムに算出する。

### 原則2：全要素の自己完結パッケージ化 ＋「頭脳（振る舞い）」と「見た目（Renderer）」の分離 ＋ 複合操作の単一トランザクション化
- **頭脳と見た目の完全分離**:
  - ツールに限らず、すべてのキャンバスオブジェクト（選手マーカー、ボール、矢印、ゾーン、テキスト、コネクタ）、右パネル（Formation / Squad）、タイムラインをそれぞれ独立したモジュールとして構成する。
  - 各モジュールは **「頭脳（状態更新・ドラッグ移動・選択・検証を担うロジック/Hook）」** と **「見た目（Konva描画・React UIのRenderer）」** を明確に分離し、UIコンポーネント内に直接の座標計算式や複雑な状態書き換えを書かない。
  - **選手マーカーの共通化**: 位置・ドラッグ移動・選択・オブジェクトオプション制御の「頭脳」と「マーカー下部の選手名ラベル表示」は1箇所で共通管理し、Web版の「2D丸マーカー」とExtension版の「3D足元リング」は見た目（Renderer）とホスト固有項目（背番号入力の有無、削除ボタンの有無）のみを差し替える。
- **複合操作の単一トランザクション化（Atomic Commands）**:
  - 「メンバー維持リセット」「アスペクト比切替」「フォーメーション適用」「Home/Away/Both一括変更」「ベンチ移動」などの複数データを同時に動かす操作は、ボタンの `onClick` 等に個別記述せず、ストア内の**1つの純粋コマンド関数**に集約する。どのUIから呼び出しても100%同じ処理を通ることで同期漏れバグを防ぐ。
- **ホスト別カタログ方式**:
  - Web版とExtension版のツールバー構成やオプションの違いは、コード内の `if` 分岐ではなく、起動時に注入するカタログ設定で宣言的に切り替える。

### 原則3：2D作図キャンバスの完全平面化 ＆ 3Dカメラ（スプリットプレビュー・エクスポート）座標変換と5層レイヤー構造
作図の正確性と操作性を極限まで高めるため、メインキャンバスは「作業用ズーム・パンが可能な完全平面2Dビューポート（傾き0°）」として維持し、3Dカメラ操作（チルト・ヨー回転・パン・ズーム・6大プリセット）は独立した「3Dスプリットプレビューワークスペース」およびエクスポートパイプラインに集約する。

1. **3段階の座標空間（Coordinate Spaces）と単一変換パイプライン（`CameraProjection`）**:
   - **① ピッチ論理座標（World / Pitch Space: `0〜100`）**:
     ストアに保存される唯一の永続化座標。アスペクト比変更や3Dカメラ操作（チルト・回転・ズーム）によって、ストア内の選手や矢印の論理座標データを書き換えてはならない。
   - **② キャンバス平面座標（Stage 2D Space: `px`）**:
     メインキャンバス中央に配置される、選択アスペクト比の「ピッチ枠（`PitchRect`）」への基準2Dマッピング座標。2D編集キャンバスではこの平面空間上でマウス操作・作図・ドラッグが完結する。
   - **③ スクリーン投影座標（Screen / Camera Space: `px` + `perspectiveScale`）**:
     3Dカメラパラメータ `CameraState = { tilt, yaw, zoom, panX, panY }`（Tilt: 0〜70°, Yaw: 0〜360°）を適用した最終3D描画座標および奥行きスケール。スプリットプレビューおよび動画書き出しで使用される。
   - **単一変換の原則**:
     - 3Dプレビュー描画、アニメーション再生、エクスポート、3D足元リングの投影は、すべて単一の正変換関数 **`worldToScreen(worldPos, pitchRect, camera)`**（`gl-matrix` MVPマトリクス）を参照する。
     - 2Dキャンバスでのマウスクリック、ドラッグ移動、ベンチからのドロップ位置算出は、すべて単一の逆変換関数 **`screenToWorld(screenPos, pitchRect, camera)`** を参照する。

2. **カメラ・純粋描画に対応する 5層レイヤー構造（Konva Layers & Overlays）**:
   - **Layer 1: `PitchGroundLayer`（地面・平面投影レイヤー）**:
     ピッチ背景（ソリッド `#0B303E` または大理石テクスチャ `pitch-marble-texture.jpg`）、サイアン白線枠（`PitchFrame`、`#38bdf8`）、地面に塗られるゾーン（`Zone`）、地面上を走る矢印・直線・ルートルート線（`route_line`）・コネクタ・ゴースト軌道のライン。
   - **Layer 2: `BillboardObjectLayer`（ビルボード・立ちオブジェクトレイヤー）**:
     選手マーカー（2D丸マーカー / 3D足元リング＋下部の選手名ラベル）、ボール、テキスト。
     足元の基準位置 `(x, y)` は奥行きに応じた遠近スケール（`perspectiveScale`）が掛かるが、**選手マーカーの円や文字自体は縦に潰れず常にカメラ正面（正円・読める文字）を向くビルボード方式**とする。また、手前の選手が奥の選手の前に重なるよう、スクリーンY座標（深さ）で描画順ソート（`sortBillboardItemsByDepth`）を行う。
   - **Layer 3: `InteractionPreviewLayer`（作図プレビュー・編集補助レイヤー）**:
     作図中のプレビュー図形、範囲選択ボックス、選択ハイライト枠、ゴースト軌道の操作ハンドル、矢印・ゾーンの頂点・曲率ハンドル。
   - **Overlay 1: `ViewportCropOverlay`（画面基準の境界線枠レイヤー）**:
     境界線枠（`BoundaryBox`）と外側マスク。カメラの傾きに依存せず、常に画面に対して水平・垂直な出力切り抜き枠として機能する。
   - **Overlay 2: `HtmlHudOverlay`（オブジェクトオプション・境界線オプション）**:
     選択中オブジェクトのスクリーン座標に追従して浮動表示される React UI メニュー。

### 原則4：境界線枠による出力一致 ＆ 再生・出力時の純粋描画（Clean Render）
- **出力範囲の不変条件**: 静止画（PNG）も動画（プレビュー再生・WebM/MP4出力）も、キャンバス上で境界線枠が表示中か非表示かに関わらず、常に内部で保持されている**「境界線枠（BoundaryBox）の領域」**がそのまま出力範囲となる（※GIF出力は廃止し、短尺アニメーションもすべてMP4/WebM動画として出力する）。
- **純粋描画の不変条件**: アニメーション再生中および画像・動画の出力時は、以下の**編集用補助表示（Layer 3 および Overlays）をすべて完全に非表示**にし、オブジェクト本来の見た目のみを描画する：
  - 選択状態の強調（ハイライト枠・リング）
  - オブジェクトオプション（メニューバー）
  - 境界線枠（破線枠・外側マスク）および境界線オプション
  - ゴースト軌道（半透明マーカー・点線矢印・曲線ハンドル）
  - 矢印の端点・曲率ハンドル、ゾーンの頂点・回転ハンドル

### 原則5：車輪の再発明（自前実装）の禁止と標準ライブラリへの完全委譲
複雑な計算やブラウザ互換処理を自前で手書きしてバグを生むことを防ぐため、各領域は以下の採用ライブラリに100%委譲し、旧来の自前実装・廃止パッケージは完全に撤去する：
- **アニメーション再生・イージング・将来のカメラ補間**: **`gsap` + `@gsap/react`**（`useGSAP` / `contextSafe` / `gsap.timeline()`）に統一する。自前の `requestAnimationFrame` ループ管理や自前イージング関数（`easing.ts`）は廃止する。将来のカメラ操作（チルト・左右回転・ズーム・リセット）の滑らかな遷移もすべて `useGSAP` で制御する。
- **キーボードショートカット**: **`react-hotkeys-hook`** に一元化する。自前の `window.addEventListener('keydown')` による修飾キー分岐（`use-keyboard-shortcuts.ts` / `canvas-shortcuts-handler.ts`）および旧 `hotkeys-js` は廃止する。
- **オブジェクトオプション（HUD）・ポップオーバーの位置自動調整**: **`@floating-ui/react`**（`flip()`, `shift()`, `offset()`）に委譲し、画面端での上下反転・左右クランプを自動化する（自前の固定値クランプ計算 `use-hud-position.ts` は廃止）。
- **カラーピッカーUI**: **`react-colorful`** を使用し、ポップオーバー内で完結する色変更UIに統一する（OS依存の `<input type="color">` 透明重ねハックは廃止）。
- **動画・静止画・ZIP出力**:
  - **動画（MP4 / WebM）**: **`mediabunny`** の高レベルAPI（`CanvasSource` 等）に委譲し、旧 `mp4-muxer` / `webm-muxer` および自前の WebCodecs `VideoEncoder` チャンク管理コードを廃止する。
  - **静止画（PNG）**: Konva 標準の **`stage.toBlob()`** を直接使用し、旧 `html-to-image` や自前の `dataUrlToBlob` 変換を廃止する（`gif.js` によるGIF出力も完全廃止）。
  - **ZIP圧縮**: 高速・軽量な **`fflate`** に統一し、旧 `jszip` を廃止する。

## 4. 機能別詳細仕様

### 4.1 メインキャンバス・3Dスプリットプレビュー・アスペクト比・ピッチ外観
1. **アスペクト比とピッチの向き**:
   - 新規プロジェクト・初期状態のデフォルト比率は **`4:5`** とする。
   - **横向きピッチ**: `16:9` のみ。
   - **縦向きピッチ**: `4:5`、`9:16`、`1:1` の3種類。
2. **2D編集キャンバスの作業用ズーム・パンと完全平面化**:
   - メインキャンバスは傾き0°の完全平面2D空間として動作し、ピッチ上への作図・ドラッグ・選択操作のブレを排除。
   - 作業領域としての独立パン・ズームに対応し、ピッチ外側の作業余白も活用可能。
   - ショートカットキー **`\`** により、左右パネルやトップバーを隠してキャンバスを最大化する「フォーカスモード」を瞬時に切り替え可能。
3. **ピッチ外観カスタマイズ（Pitch Appearance）**:
   - **ライン色**: デフォルトでモダンなサイアン系ライン（`#38bdf8`）を採用し、ライン太さ（1〜6px、デフォルト2.5px）、ライン不透明度（0〜1.0）を変更可能。
   - **背景タイプ**: ベタ塗りソリッド（`solid`、デフォルト `#0B303E`）と、重厚な大理石テクスチャ（`marble`、`pitch-marble-texture.jpg`）を選択可能。
   - 大理石テクスチャ選択時は、上下左右3%余白の内側ピッチ面のみに美しくクリップされ、カラーオーバーレイ合成と透過度調整が可能。
4. **境界線枠（BoundaryBox）の内部初期状態とキャンバス上の非表示デフォルト**:
   - **内部データの初期状態**:
     - **Web版**: 初期状態（および比率変更・リセット時）は、内部的に**「ピッチ枠」にぴったり合わせた範囲**をデフォルトの境界線状態として保持する。
     - **Extension版**: 初期状態は、内部的に**「スクリーンショット（キャンバス全体＝100%）」に合わせた範囲**をデフォルトの境界線状態として保持する。
   - **キャンバス上の初期表示状態（デフォルト非表示）**:
     - 初期状態（およびリセット時）では、ツールバーの「境界線表示」は**非選択（OFF）状態**とし、**メインキャンバス上に境界線枠（破線枠・外側マスク）および境界線オプションは見えない状態**にする。
     - ユーザーがツールバーの「境界線表示」ボタンを押してONにした時のみ、キャンバス上に境界線枠と上部の **境界線オプション**（「全画面」「ピッチにフィット」の2ボタン）を表示し、枠の調整を行えるようにする。

### 4.2 ツールバー（右上）の構成
1. **Web版ツールバー**:
   - `選択 (V)`
   - `直線 (L)`
   - `ルートルート線 [Route Line] (R)`: 選手の流動的な走行・ダイナミックな侵入ルートを表現する曲線追従ライン。
   - `実線矢印 (A)` / `破線矢印 (D)` / `波線矢印 (W)`
   - `矩形ゾーン (Z)` / `多角形ゾーン (P)`
   - `テキスト (T)`
   - `ピッチ固定（ロック）`
   - `境界線表示切替`（初期状態はOFF＝非表示）
   - `連続配置ロック`
   - `消しゴム (E)`
   - ※Web版のツールバーには「2D選手マーカー配置ボタン」および「3D選手マーカー配置ボタン」は置かない（Web版の選手追加は右パネルの `Squad` タブから行う）。
2. **Extension版ツールバー**:
   - Web版共通の作図ツール群 ＋ **`3D選手マーカー（足元リング O）`** ＋ **`3Dフェードリング（F）`**（透過グラデーションとグロー効果を備えた足元リング）を配置する。
   - ※Extension版には「2D選手マーカー」および「ピッチ固定」は置かない。

---

### 4.3 オブジェクトオプション（選択時メニュー）＆ マーカー下の名前表示
オブジェクトを1つ選択した際に対象の近くに表示し、ドラッグ移動開始と同時に非表示にする。画面端（上端・左右端）では見切れないよう自動で表示位置（上下反転・左右クランプ）を調整する。

1. **マーカー下部の選手名ラベル表示 ＆ 2D/3Dマーカーの中央表示仕様（Web 2D / Extension 3D）**:
   - Web版（2Dマーカー）で試合詳細からの遷移時や名前設定時にマーカーの下部に選手名が表示されるのと同様に、**Extension版（3Dマーカー）でも名前を追加・設定した際は、3Dマーカー（足元リング）の下部に選手名ラベルを表示する**。
   - **2D丸マーカー（`circle`）の内部表示（`insideContent`）**: `Num`（背番号）、`Photo`（`player_photos` テーブルの256×256 WebP顔写真を円内にクリップ描画。`playerId` が未一致の場合でも選手氏名の一致によるフォールバック検索で安全に描画。未登録選手は背番号表示にフォールバック）、`Empty`（円内は何も表示しない）の3モードに対応する。
   - **3D足元リング（`ring` / `ring-fade`）の内部表示**: 足元リングの中央には何も表示しない（背番号や顔写真をリング中央に描画することはなく、下部の選手名ラベルのみを表示する）。
2. **選手マーカー（Web版・2Dマーカー）のオブジェクトオプション**:
   - `視野（Vision Cone）`: 扇形の視野表示のON/OFF（向き・角度・長さをドラッグ操作可能、カラーピッカーで色・透過度を変更可能、デフォルト `#38bdf8` / 透過度0.3 / 半径13）。
   - `コネクタ`: 主に味方同士の戦術的な繋がりを表現するラインの追加・解除。
   - `矢印3種（実線・破線・波線）`: その選手を起点とする矢印をワンクリックで追加。
   - `フォーカス（強調）`: スポットライト強調のON/OFF。
   - `ロック`: 誤操作防止の位置固定ON/OFF。
   - `選手情報変更ボタン`: ボタンを押すとミニフォーム（ポップオーバー）が開き、**`背番号`** と **`名前`** を変更できる。
   - `中の色変更` / `枠の色変更`: メインカラーと枠線カラーをカラーピッカーで変更。
   - `大きさ変更`: マーカーのスケール（`-` / `+`）を変更。
   - ※Web版では「削除」ボタンおよび「ベンチへ移動」ボタンは置かない（ベンチへの移動はドラッグ＆ドロップで行う）。
3. **選手マーカー（Extension版・3Dマーカー）のオブジェクトオプション**:
   - `視野` / `コネクタ` / `矢印3種` / `フォーカス` / `ロック`
   - `選手情報変更ボタン`: ボタンを押すと **`名前`** を変更できるフォームを開き、入力した名前を3Dマーカーの下部に表示する。
   - `色変更`: リングの色を変更。
   - `大きさ変更`: スケール（`-` / `+`）を変更。
   - `削除`: マーカーを削除するゴミ箱ボタン。
4. **その他のオブジェクト（矢印・ゾーン・テキスト・コネクタ・ボール）**:
   - **矢印 / 直線 / ルートルート線 / ツールバーコネクタ**: 色変更、太さ変更、線種切替（実線/破線/波線）、ロック、削除。
   - **コネクタ（選手間）**: 実線/点線切替、太さ変更、色変更、削除。
   - **ゾーン**: 色変更、不透明度、枠線色、枠線不透明度（`strokeOpacity: 0〜1.0`）、枠線太さ、ロック、削除。
   - **テキスト**: テキスト再編集、文字サイズ変更、色変更、ロック、削除。

### 4.4 右パネル（Formation / Squad / Pitch）・試合連携・リセット
右パネルは **`Formation`**、**`Squad`**、**`Pitch`** の3タブ構成とする（48pxミニマルアイコンレールに折りたたみ可能）。

1. **Formation タブ**:
   - **ピッチ展開モードのデフォルト**: `Half` / `Full` 切替のデフォルトは **`Full`**（フルピッチ配置）とする。
   - **対象チームセレクター（`Home | Away | Both`）**:
     - トップバーと同様に **`Home | Away | Both` の3択ボタン** を上部に配置する。
     - ユーザーはこの `Home | Away | Both` のいずれかを選択した状態で、以下の3つの設定を直接（選択対象に対して一括で）変更できる：
       1. **チームカラー変更（色変更）**: 選択中の対象（Home / Away / Both）のチームカラーを変更する。
       2. **フォーメーション変更（プリセット選択）**: 選択中の対象（Homeのみ / Awayのみ / Both＝両チーム同時）にフォーメーションプリセットを適用し、ピッチ白線枠内の適切なポジション座標（GKはゴールライン直前の定位置）へ配置する。この際、**各選手の元のポジション情報（GK, CB, LB, RB, DM, CM, AM, LW, RW, CF 等）は上書きせず保持し、縦ラインと左右レーン（左・中央・右）の適性が一致する枠へ自動マッチングして配置する**。また、試合データ連携時（`matchFormations` 保持時）は、選択中のチーム（Home / Away）の試合フォーメーションがプリセット一覧上で選択状態として連動表示される。
       3. **マーカー内の表示変更**: 選択中の対象（Homeのみ / Awayのみ / Both＝両チーム全員）の選手マーカー内部の表示モード（`Num`［背番号］ / `Photo`［写真］ / `Empty`［空］）を一括変更する。
   - **陣地反転（Swap）**:
     - 実行すると、ピッチ上の選手マーカー（`area === 'pitch'`）、ボール、矢印、ゾーン、テキストをすべて**ピッチ中心 `(50, 50)` を基準に 180度点対称回転（`x' = 100 - x, y' = 100 - y`）**させる。
     - **ベンチキャンバス上の控え選手（`area === 'bench'`）は反転対象外**とし、グリッド配置を維持する。
     - 反転状態（`isSidesSwapped`）はスライドごとに保持され、Swap 適用後にフォーメーションプリセットの再選択や「メンバー維持リセット」を行った場合も、反転後の陣地（Home が右/上陣地、Away が左/下陣地）を維持して配置する。

2. **Squad タブ ＆ ベンチキャンバス（サブキャンバス）**:
   - **Club & Season Presets（通常ボード専用）**:
     - クラブ・シーズン別の選手プリセット読込機能を配置する（チェルシー公式WhoScored ID同期済み）。
     - この機能は**通常の戦術ボード（`matchId` なし）の時のみ表示・適用可能**とし、試合詳細経由の戦術ボード（`matchId` あり）では非表示とする。
   - **選手追加フォーム**: 背番号・ポジション・名前を入力して選手を追加できる。
   - **ベンチキャンバス（サブキャンバス）**:
     - 控え選手のマーカーが配置される領域。ベンチキャンバス内でもマーカーを自由にドラッグ移動できる。
     - **「整理」ボタン**: ベンチキャンバス内の選手をポジション順（GK / DF / MF / FW）のグリッドに綺麗に整列させる。
   - **メインキャンバス ⇄ ベンチキャンバスの双方向ドラッグ＆ドロップ**:
     - ベンチキャンバスからメインキャンバスへ選手をドラッグ＆ドロップすると、ドロップした位置に投入される。
     - メインキャンバスからベンチキャンバスへ選手をドラッグ＆ドロップすると、ベンチキャンバスへ退避する。
     - **退避時のオプション自動初期化**: ベンチへ移動した選手は、`視野`・`フォーカス`・`コネクタ`・`起点矢印`・`ゴースト軌道` などの個別オプションがすべて自動的にクリアされる。

3. **Pitch タブ（ピッチ外観調整）**:
   - **背景タイプ**: Solid / Marble の切り替え。
   - **オーバーレイ設定**: オーバーレイカラー（カラーピッカー）および不透明度スライダー。
   - **ライン設定**: ラインカラー（カラーピッカー）、ライン太さ（1〜6px）、ライン不透明度（0〜1.0）。
   - プロジェクト全体で一元管理され、スライド切り替え・動画書き出し・エクスポートプレビューに即座に反映される。

4. **試合詳細からの遷移連携（`/tactical?matchId=xxx`）と永続化キー分離**:
   - **自動配置（クラブ戦データ対象）**:
     - 指定分数における `formation.formationSlots`（`1〜11`＝スタメン、`0`＝控え）と縦横スロット座標から、11人の役割と左右位置関係を正確に紐づけてメインキャンバスへ自動配置する。
     - ベンチキャンバスには未出場の控え選手（スロット0）を先頭に、すでに交代で退いた先発選手をその後ろに並べて配置する。
   - **永続化キーの完全分離**:
     - 通常の戦術ボードは `tactical_project_${id}`、試合連携ボードは `tactical_project_match_${matchId}` として別々の Dexie レコードで永続化され、試合分析時の作図データが通常ボードへ上書き混入することを防ぐ。
   - **試合詳細経由ボードでの `New Project` 作成**:
     - 試合詳細経由の戦術ボードで `New Project` を実行した場合は、その試合の出場・控えメンバーと各チームの試合フォーメーションを引き継いだ「試合詳細版の戦術ボード」として新規プロジェクトを作成・初期化する。

5. **トップバーの「メンバー維持リセット」**:
   - 押下すると、**現在のスタメン・ベンチのメンバー構成（選手ID・名前・背番号・所属チーム）はそのまま維持**し、以下の初期化を行う：
     - **フォーメーション位置への再配置**: 通常ボードは初期フォーメーション（Home `4-2-3-1` / Away `4-4-2`）、試合連携ボードは試合の実際のフォーメーションを採用し、GK定位置を含めて再配置する。
     - ボールを中央 `(50, 50)` へ戻す。
     - 境界線枠の内部データを初期状態（Web版＝ピッチ枠フィット）へ戻し、キャンバス上の境界線表示をOFF（非表示）にする。
     - 矢印・ゾーン・テキストおよび選手個人のオプション（視野・フォーカス・コネクタ・ゴースト軌道）をすべて消去する。

### 4.5 3Dスプリットプレビューワークスペース (Split Preview Workspace)
トップバーの `Columns2` ボタンを押すことで、メインキャンバスの右側に開くリアルタイム3Dカメラプレビュー画面です。

1. **画面構成**:
   - 2D編集キャンバス（左側）と、3Dカメラプレビュー（右側）が並列表示され、2Dキャンバスでの編集（選手の移動、矢印の追加、フォーメーション変更）がリアルタイムに3D視点へ反映される。
2. **直感的なカメラ操作**:
   - **オービット（Tilt & Yaw）**: プレビューキャンバス上を左ドラッグ（Shiftなし）。上下ドラッグでチルト角（`0°〜70°`）、左右ドラッグでヨー旋回（`0°〜360°`）を滑らかに調整。
   - **パン（Pan）**: `Shift + 左ドラッグ` でカメラの視点中心位置（`panX, panY`）を平行移動。
   - **ズーム（Zoom）**: マウスホイール操作で `0.5x 〜 2.5x` の範囲で拡大縮小。
3. **6大カメラプリセットUI**:
   - `トップダウン（完全平面・縦向き）`: Tilt 0°, Yaw 90°
   - `浅い俯瞰（正面）`: Tilt 15°, Yaw 90°
   - `浅い斜め（右向き）`: Tilt 15°, Yaw 75°
   - `浅い斜め（左向き）`: Tilt 15°, Yaw 105°
   - `ダイナミック斜め（右向き）`: Tilt 50°, Yaw 80°
   - `ダイナミック斜め（左向き）`: Tilt 50°, Yaw 100°
   - カメラリセットアイコンを押すと初期状態（Tilt 0°, Yaw 90°, Zoom 1.0x, Pan 0, 0）にワンクリックで復帰。
4. **描画・アニメーション同期**:
   - 高解像度 Canvas2D レンダラーにより、選手顔写真（WebP）、大理石背景テクスチャ、矢印・波線・ゾーンを忠実にレンダリング。
   - 下部再生コントロールでシーン連続再生・シーク・時間表示（例: `1.2s / 4.5s`）が可能。

## 5. フェーズ構造・タイムライン・ゴースト軌道・アニメーション再生
1. **フェーズ構造（TacticalPhase）とシーン（スライド）管理**:
   - プロジェクトデータはトップレベル直下にスライドをフラットに持たず、PowerPoint風の **`phases: TacticalPhase[]`（フェーズフォルダ）** 構造を採用する。
   - **左パネル（LeftPanel）**: フェーズの追加・削除・名称変更が可能。各フェーズ内のシーン一覧には、実際のピッチ配置（選手・ボール・矢印等）が 2D キャンバス縮小描画（リアルタイムサムネイル）として表示される。
   - タイムラインバーでのシーン操作（追加・空シーン追加・複製・削除・DndKit 並び替え）およびアニメーション再生・補間は、**現在アクティブなフェーズ内の `slides` にスコープ**され、フェーズを跨いだ誤再生や予期せぬジャンプを防止する。
   - **シーン複製ショートカット**: キーボードの **`Mod + M`**（Mac: `Cmd + M`, Windows: `Ctrl + M`）を押すことで、現在選択中のシーンを瞬時に複製可能。
   - **タイムライン横スクロール**: タイムラインバー上にポインターがある際、マウスホイール操作でタイムラインを水平方向に滑らかにスクロール可能。
   - **シーンカード内表示の整理**: カード本体には静止時間（例: `静止 0.5s`）と配置オブジェクト数（選手・矢印・ゾーン）のみを簡潔に表示し、移動時間はシーン間コネクタへ分離して視認性を確保。
   - **カード操作オーバーレイ（`SlideCardActions`）**: カードホバー時に表示される操作アイコン群（複製・削除・個別設定等）は枠内右上（`top-1 right-1`）に半透明背景オーバーレイとして収容し、タイムライン上端での見切れや DndKit のドラッグ干渉を防止。
2. **シーン間トランジション ＆ 移動・静止・加減速・3Dカメラスロードリフト設定**:
   - **シーン間トランジションコネクタ（`TransitionConnector`）**: シーンカード間に小型コネクタを配置し、到着先シーンへの移動時間（秒）を「── 1.0s ──▶」形式で直感的に表示（クリックで設定ポップオーバー展開）。
   - **個別シーン設定ポップオーバー（`SlideTransitionPopover`）**:
     - `@floating-ui/react` の **`FloatingPortal`** により画面最前面に展開。
     - 移動時間（0.1s〜10.0s）、静止時間（0.0s〜5.0s）、加減速（等速 `linear`、滑らか `ease-in-out`、加速 `ease-in`、減速 `ease-out`）を調整可能。
     - **3Dカメラトランジションモード（`cameraTransitionMode`）**: `sync`（シーン移動時間と同期して補間）、`slow`（長時間の緩やかなスロードリフト）、`continuous`（複数シーン跨ぎの継続カメラワーク）、`cut`（シーン切り替え時に瞬時カット）を選択可能。カメラ補間時間（`cameraDurationMs`: 500ms〜60000ms、デフォルト 10000ms）も個別設定できる。
   - **全シーン一括設定ポップオーバー（`BatchTransitionPopover`）**:
     - タイムラインバー右側の「一括設定」ボタンから開き、全シーンの移動時間・静止時間・加減速をまとめて一度に変更（1手のアンドゥで復元可能）。
   - **到着先シーン基準の総時間統一**:
     - 総再生時間計算（`calculateUnifiedTotalDuration`）および補間フレーム計算は到着先スライド基準に統一され、スライド1枚時は `0.0s`、2枚目以降はそのシーンへの移動時間＋静止時間の合計となり、再生コントロールの表示時間と実際の動画時間が 100% 一致する。
3. **ゴースト軌道（GhostTrajectory）の仕様**:
   - **表示条件**: シーン2以降で前のシーンから位置が移動した選手・ボールについて、**その選手（またはボール）が「選択状態」または「ドラッグ移動中」の時のみ**ゴースト軌道（前シーン位置の半透明表示＋点線矢印＋曲線ハンドル）を表示する。非選択時は表示しない。
   - **リアルタイム追従**: 選手やボールを**ドラッグし始めた瞬間（1ピクセル目）から**、ゴースト軌道の点線矢印の先端と曲線ハンドルが現在位置に遅れなくリアルタイム追従する。
   - **曲線調整**: ゴースト軌道の中央ハンドルをドラッグすることで移動ルートを曲線（ベジェ曲線）に曲げることができ、アニメーション再生時もその曲線ルート通りに動く。
4. **アニメーション再生**:
   - 下部タイムラインの再生ボタンまたはスペースキーで、シーン1から最終シーンまで連続再生する。
   - **GSAP タイムライン統括**: `gsap.timeline()` により再生・一時停止・シーク・位置同期を一元管理し、自前 rAF ループは全廃。コンポーネント破棄時や再生停止時には必ず `timeline.kill()` による RAII クリーンアップを徹底。
   - **再生中の純粋描画（Clean Render）**: 再生開始（`isPlaying || isExporting`）と同時に、選択枠・オブジェクトオプション・境界線枠・ゴースト軌道等の編集用UIをすべて隠し、選手・ボール・矢印・ゾーン・テキストの本来の見た目だけを滑らかにアニメーションさせる。
   - 再生完了後または一時停止時、すべてのマーカーとボールが消失・座標ズレを起こさず正確な位置に保たれる。
