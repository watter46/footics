# 🔧 L1-CLI-006: ticket-done.tsへのHandover仮チケット自動解決・コミット機能の統合

## UX Impact
`make done TOKEN-OPT-001` のように、正規チケット以外の仮チケット・引継ぎ（Handover）ファイルも同一コマンドで自動判定して完了・コミット可能になります。引継ぎ作成時や手動チケット管理での個別 git コミットの手間とヒューマンエラーを排除し、シームレスな開発フローを実現します。

## Detailed Spec
### 背景・現状の課題
現在の `ticket-done.ts` は `.regista/tickets/${id}.md` のみを探索対象とし、かつ Frontmatter 形式のチケットのみを前提としています。また `validate-tickets.js` による厳格なバリデーションや `validateDiffGate` による厳格な未記載ファイルチェックが行われるため、仮チケット（引継ぎ・Handover）ファイルを `make done` で完了コミットしようとするとファイル未検出エラーやバリデーションエラーになります。

### 変更詳細
1. **TicketInfo の拡張**:
   - `interface TicketInfo` に `type: 'ticket' | 'handover'` プロパティを追加し、正規チケットと Handover を区別する。

2. **`loadTicket` の探索ロジック拡張（自動解決・相互解決）**:
   - まず `.regista/tickets/${id}.md` を優先探索する。
   - 見つからない場合、`.regista/handover/` 配下を以下の優先順位で探索する:
     - 入力IDそのまま: `.regista/handover/${id}.md`
     - `-handover` を付与: `.regista/handover/${id}-handover.md`
     - `-handover` が既にある場合は除去: `.regista/handover/${cleanId}.md`（`cleanId = id.replace(/-handover$/, '')`）
   - これにより、`make done TOKEN-OPT-001` でも `make done TOKEN-OPT-001-handover` でも同一の引継ぎファイルを自動解決できる。

3. **Handover ファイルのメタデータ・変更ファイル抽出**:
   - **タイトル**: Frontmatter に `title:` があればそれを利用。無ければ `# 引継ぎサマリー: ...` または先頭の見出し（`# ...`）から抽出。
   - **変更ファイル一覧**:
     - `## 4. 現時点の実装状況` 内の番号リスト（例: `1. **`filepath`**:` 等）からファイルパスを抽出。
     - 取得できない場合は `## 1. タスク概要` の「関連ファイル」セクションからバッククォートで囲まれたパスを抽出。

4. **`markTicketDone` の Handover 対応**:
   - Frontmatter に `status:` が存在する場合は `status: DONE` に置換。
   - Frontmatter が無い場合は、本文中の `- **ステータス**: ...` 行を `- **ステータス**: DONE` に置換、または先頭ヘッダー直後にステータス行を挿入/更新する。

5. **`runValidation` のスコープ制御**:
   - `tickets` に含まれる全アイテムが `type === 'handover'` の場合、`.agents/scripts/validate-tickets.js` の実行をスキップする（Handover ファイルはチケット用スキーマを満たさないため）。
   - 正規チケット（`type === 'ticket'`）が含まれる場合は従来通り実行する。

6. **`validateDiffGate` の柔軟化**:
   - Handover 対象の場合、他ドメインや作業中の差分がワーキングツリーに残っていてもブロック（`process.exit(1)`）せず、警告（warning）を出力した上で Handover に記載されたファイルのみをステージング・コミット対象として許可する。

7. **コミットメッセージ生成の分岐**:
   - `generateCommitMessage` において、Handover の場合は `docs(handover): done ${id} - ${title}` を生成する。

8. **`.regista/templates/handover.md` のテンプレート改修**:
   - 「## 1. タスク概要」に `- **ステータス**: `IN_PROGRESS` # IN_PROGRESS | DONE` 行を追加し、Handover のパースおよびステータス遷移をより堅牢にする。
