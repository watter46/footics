# 🟢 L1-CLI-003: チケットバリデータのBLOCKED追加とWrite-back厳格化

## UX Impact
WorkerがFail-Fast中断でBLOCKEDに更新した際にスキーマエラー警告が出なくなり、またWrite-back未記入のまま完了する事故を機械的に防止できます。

## Detailed Spec
1. `.agents/scripts/list-tickets.js` の `TicketSchema` において、`status` の enum に `'BLOCKED'` を追加する。
   ```javascript
   status: z.enum(['TODO', 'IN_PROGRESS', 'REVIEW_QA', 'DONE', 'BLOCKED']).default('TODO'),
   ```
2. `.agents/scripts/validate-tickets.js` において、チケットの `status === 'DONE'` 時に Write-back ログがテンプレートのまま未記入である場合（`isUnfilled === true`）、`warnings.push` ではなく `errors.push` に追加してバリデーションを失敗（exit 1）させる。
3. エラーメッセージは「Write-back incomplete: status is 'DONE' but Implementation Log is empty template. Please fill out Write-back Log.」とする。

## Acceptance Criteria
- [ ] `node .agents/scripts/list-tickets.js` を実行した際、`status: BLOCKED` のチケットがあっても Zod スキーマエラー警告が発生しないこと。
- [ ] `status: DONE` かつ Write-back 未記入のチケットが存在する場合、`node .agents/scripts/validate-tickets.js` が exit 1 でエラー終了すること。

## Verification Commands
```bash
node .agents/scripts/list-tickets.js
node .agents/scripts/validate-tickets.js
```
