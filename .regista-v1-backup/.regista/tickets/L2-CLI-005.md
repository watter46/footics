# 🟡 L2-CLI-005: ticket-doneスクリプトのgit status突合・削除ファイル対応・アトミック化

## UX Impact
`make done` 実行時に、Workerの書き漏らした変更ファイルによるコミット欠損を100%防止し、ファイル削除タスクでも正常に完了できるようになり、コミット失敗時にチケット状態が壊れなくなります。

## Detailed Spec
1. **削除ファイル（`git rm`）の許容**:
   - `validateAndResolveFiles` において、`fs.existsSync(fullPath)` が false であっても、Git上で削除されたファイル（`git status --porcelain` または `git ls-files --deleted`）に含まれている場合はエラーとせず、有効な変更ファイルとして解決する。
2. **`git status` と Write-back 変更ファイル一覧の突合（Diff Gate）**:
   - `git status --porcelain` を実行し、現在ワーキングツリーで変更・追加・削除された全ファイルの一覧（対象チケット以外の未ステージングファイル）を取得する。
   - チケットに記載された `changedFiles` と Git の実際の変更ファイル群を突合する。
   - もし Git で変更・作成されているのにチケットの「変更ファイル一覧」に記載されていないファイルが存在する場合、以下のエラーを出力して `process.exit(1)` で停止する:
     ```
     ❌ Error: Write-back の変更ファイル一覧と Git の実際の変更に乖離があります。
     未記載の変更ファイル:
       - <未記載ファイルパス>
     Workerに Write-back を追記させるか、チケットを更新してください。
     ```
3. **アトミックなトランザクション処理（ロールバック対応）**:
   - チケットのバックアップ（元内容）をメモリに保持する。
   - `markTicketDone` は `runValidation` の直前ではなく、バリデーション通過後に実行する（またはバリデーション時のみ一時反映）。
   - `git commit` が何らかの理由で例外をスローした場合、チケットファイルを元の状態に書き戻してロールバックしてから終了する。

## Acceptance Criteria
- [x] 削除されたファイルがチケットの変更ファイル一覧に含まれていても `ticket-done.ts` が正常にステージングできること。
- [x] チケットの「変更ファイル一覧」に未記載の変更ファイルがワーキングツリーにある場合、`make done` がエラーを出してコミットを中断すること。
- [x] コミット失敗時にチケットファイルの `status: DONE` がロールバックされること。
