# Knowledge Update ワークフロー

**トリガー:** `/knowledge-update` (または AI が設計変更を伴うタスクの完了時に自律的に発動)

**説明:**
プロジェクトの設計仕様やアーキテクチャに変更があった際、リポジトリ内の Knowledge Items (KI) を最新の状態に同期、あるいは新規作成するためのプロセスです。AIが自律的にコンテキストを維持・学習するエコシステムの要となります。

---

## 1. 状況の分析 (Analyze Context)
- **目的:** 何が変更されたか、それがどの KI に影響するかを特定する。
- **アクション:**
  - 最新の実装や新たに作成された仕様書（例: `docs/specs/` 配下のファイル）を確認する。
  - `.agents/knowledge/` 配下を検索し、更新対象となる既存のトピックが存在するか確認する。
  - 既存のトピックがない場合は、新しいトピックディレクトリ (`[topic-name]`) の作成を決定する。

## 2. 知識の蒸留 (Distillation)
- **目的:** 長大な仕様や複雑なコードから、AI向けの「ルール・制約・プロトコル」を抽出する。
- **アクション:**
  - 変更内容から「AIが今後の実装で必ず守るべき制約」を箇条書きでまとめる。
  - 過去のアンチパターンや、特定のライブラリの利用ルール（例: 常に `Dexie` を使う、直接のDB操作を避ける等）を明確にする。
  - 重要な制約には GitHub Alerts (`> [!WARNING]`, `> [!IMPORTANT]`) を付与する。

## 3. ファイルの生成・更新 (Artifact Generation)
- **目的:** 抽出した知識を `.agents/knowledge/` に反映する。
- **アクション:**
  1. **`spec.md` (任意):** ユーザーから提供された仕様書がある場合、それを原本として保存する。
  2. **`content.md`:** 蒸留したAI向けの知識を記述する。
  3. **`metadata.json`:** 以下の形式でメタデータを作成・更新する。
     ```json
     {
       "title": "トピックのわかりやすい名前",
       "summary": "このKIがカバーする範囲の短い説明",
       "lastUpdated": "YYYY-MM-DDTHH:MM:SSZ",
       "sourceFiles": [
         "関連する仕様書や実装ファイルへの相対パス"
       ]
     }
     ```

## 4. レビューの依頼 (Request Review)
- **目的:** 作成・更新した KI が人間の意図（アーキテクチャの方向性）と一致しているか確認する。
- **アクション:**
  - タスクの最後に、「以下の KI を更新（または新規作成）しました。内容を確認してください」という旨と、変更されたファイルの絶対パスを提示する。
  - `/knowledge-update` を独立して実行した場合は、ここで処理を終了する。
