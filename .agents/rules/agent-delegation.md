# サブエージェント委任・オーケストレーション規約 (Subagent Delegation Protocol)

本ルールは、Planner や Worker がサブエージェント（research, reviewer, worker 等）を呼び出す際の、孤児化（Orphan）・結果ロスト・ゾンビタスク化を防ぐための行動規約です。

---

## 1. 委任完了契約 (Delegation Completion Contract)

1. **結果回収の義務付け**:
   - サブエージェントを `invoke_subagent` ツールで起動した親エージェントは、**必ず子エージェントから完了メッセージまたは成果物を受信・確認した上で自身のタスクを完了**しなければならない。
   - 子エージェントが実行中または未応答の状態で、親エージェントが自らターンを終了（`DONE` や完了宣言）してはならない。
2. **ゾンビタスクの禁止**:
   - サブエージェントをバックグラウンドに放置したままセッションや親タスクを切り上げてはならない。不要になったサブエージェントや応答が停止したサブエージェントは、`manage_subagents` (Action: `kill`) で確実に回収・終了させること。

---

## 2. Worker モデル動的選定基準 (Worker Model Selection)

`invoke_subagent` で Worker を起動する際、タスクの規模・難易度に応じて `Model` を切り替えてトークン効率と実装成功率を最適化する。

- **`Model: "flash_lite"` (軽量・定型タスク)**
  - 対象: 文言・メッセージ修正、定数追加、軽微なCSS/スタイル修正、単一関数の単純な引数追加など。
  - 特徴: 最速レイテンシかつ最小トークン消費。
- **`Model: "flash"` (通常・TDD実装タスク)**
  - 対象: 新規テスト作成（RED/GREEN/REFACTOR）、TypeScript型定義の変更、複数コンポーネント・モジュールにまたがる機能実装、ストア（Zustand/Dexie）連携など。
  - 特徴: 型整合性やテスト検証を自律してパスさせるための安定した推論力。

---

## 3. 成果物の明示（Final Deliverable）

1. **最終メッセージが成果物**:
   - サブエージェントは作業完了時、単に「完了しました」とだけ返すのではなく、何を作成・修正・検証したのか要約とファイルリンクを明確に親エージェントへ報告すること。
2. **証拠の添付**:
   - 検証やテストを行ったサブエージェントは、実行結果（成功ステータス、テスト件数、エラーログ等）を必ず報告に含めること。
