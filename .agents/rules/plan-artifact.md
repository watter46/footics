# Plan Artifact Specification (日本語設計計画書規約)

## 目的
`/plan` や設計計画の立案時に作成する Artifact（`<appDataDir>/brain/<conversation-id>/*.md`）の書式を標準化する。
実装詳細（コード、ファイル名、図表、システム専門用語）を排除し、**Footics のユビキタス言語（プロダクト用語）** を用いた平易な日本語で「どう変わるか」「データをどう持ち、何を廃止するか」を1分で判断できるようにする。

---

## 1. 厳格な禁止事項 (Strict Prohibitions)

以下の要素は **Plan Artifact に絶対に含めてはならない**：
1. **コードスニペット・型定義・CLIコマンド**: TypeScript のコードブロック、関数名、コマンド文字列。
2. **実装ファイル名・パス**: `src/.../foo.ts` などの具体的なファイルパス。
3. **テスト・機械検証手順**: 「〇〇のテストを実行してPASSする」「`bun run ai:check`」等の開発工程の記述。
4. **Mermaid 図・横長テーブル・生 HTML タグ**: 表示崩れや認知負荷の原因となるため使用禁止。
5. **抽象的なシステム専門用語**: 以下の対照表に従い、必ず **Footics ユビキタス言語（画面・機能・操作の言葉）** に言い換えて記述すること。

### Footics ユビキタス言語 対照表

| 分類 | 積極的に使う言葉（Footics ユビキタス言語） | 禁止する言葉（抽象的なシステム用語） |
| :--- | :--- | :--- |
| **画面・領域** | **ボード画面**、**レイアウト画面**、**エクスポート画面**、**クイック編集（拡張機能）**、**サイドパネル**、**タイムライン** | ホスト、コンシューマ、コンテナ、ビューポート、クライアント |
| **データ単位** | **プロジェクト**、**フェーズ**、**スライド**、**アニメーション再生**、**コマ送り** | ドキュメントステート、コールドステート、ホットステート、ストリーム |
| **盤面要素** | **ピッチ**、**境界線**、**ベンチ**、**選手マーカー**、**ボール**、**矢印（パス・ドリブル・ラン）**、**ゾーン**、**テキスト** | エンティティ、プリミティブ、ノード、アノテーション、ジオメトリ |
| **視覚効果** | **視野角**、**スポットライト**、**ゴースト軌道**、**パルス（波紋）**、**オブジェクトオプション**、**3D視点 / 2D視点** | ビルボード、シェーダー、イージング補間、ラスタライズ、DTO |
| **操作・状態** | **ドラッグ移動中**、**操作確定時**、**元に戻す / やり直し（Undo/Redo）**、**自動保存** | ディスパッチ、インバリアント、ミューテーション、スライス、リデューサー |

---

## 2. Plan Artifact 標準テンプレート（全タスク共通・4セクション）

機能追加・不具合修正・リファクタリングのいずれであっても、以下の構造で記述する（判断事項がない場合はセクション4を省略）：

```markdown
# {変更タイトル}

## 1. 変更後の動き（どう変わるか）
- **{画面名・操作名}**:
  - 変更前：{以前はどう動いていたか、または何が問題だったか}
  - 変更後：{今回の変更でどう動くようになるか}

## 2. データの持ち方と処理の流れ
- **基準となるデータ**: {どのデータをどこで一元管理するか}
- **操作から画面反映までの流れ**: {ユーザーの操作 ➔ データの更新 ➔ 画面への描画がどう流れるか}
- **廃止・統合するもの（該当する場合のみ）**: {今回の変更で完全に削除する古い仕組み。新旧の併用や一時的なフォールバックは一切残さないことを明記}

## 3. 壊してはいけない前提条件（他画面への影響）
- {関連する画面（例：クイック編集、エクスポート画面の動画出力、元に戻す操作など）で維持されるべき動作}

## 4. 確認したい事項（判断が必要な場合のみ）
- {仕様の選択肢がある場合のみ記載。なければ本セクションごと省略}
```
