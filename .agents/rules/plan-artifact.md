# Plan Artifact Specification (設計計画アーティファクト規約)

## 目的
Antigravity において、`/plan` や設計計画の立案時に作成する Artifact（`<appDataDir>/brain/<conversation-id>/*.md`）の書式を標準化する。
実装詳細（コード、ファイル名、テスト手順）を排除し、純粋な「アーキテクチャ・振る舞い・意思決定」の合意に特化して認知負荷を最小化する。

---

## 1. 厳格な禁止事項 (Strict Prohibitions)

以下の要素は **Plan Artifact に絶対に含めてはならない**：
1. **コードスニペット・型実装**: TypeScript/Python 等のコードブロックや関数の具体的な実装。
2. **実装ファイル名・パス**: `src/.../foo.ts` などの具体的なファイルパス（「論理モジュール名」や「ドメイン概念名」で表現すること）。
3. **テスト・機械検証手順**: 「〇〇のテストを実行してPASSする」「bun test」等の自明な開発工程の記述。
4. **Mermaid フローチャート**: 描画ズレ・崩れが発生するため、複雑な `flowchart` や `sequenceDiagram` の配置は禁止。
5. **横長 Markdown テーブル**: 3列以上、またはセル内に文章を含むテーブルは折り返し崩れ・ズレが発生するため禁止。
6. **生 HTML タグ / カルーセル**: `<details>`, `<div>`, `<mark>`, `carousel` 等はビューア環境によって無効化・サニタイズされるため多用を禁止。

---

## 2. 推奨記法 (Styling Protocol)

Antigravity ビューアがネイティブ対応している **GitHub-style Alerts** と **縦型リスト（Bold キー + インデント）** のみで構成する。

| 表現要素 | 使用用途 |
|---|---|
| `> [!NOTE]` | 計画の目的、達成基準、背景 |
| `> [!TIP]` | アーキテクチャ方針、設計思想、境界ルールの要約 |
| `> [!IMPORTANT]` | ユーザーの判断・選択・合意が必要な事項 (Open Decisions) |
| `> [!WARNING]` | 採用しなかった代替案、トレードオフ、制約事項 |
| **縦型リスト** | 決定事項や振る舞いマトリクスの記述（改行・画面幅で崩れない） |

---

## 3. Plan Artifact 標準テンプレート

Planner またはエージェントは、計画作成時に以下の構造を厳格に埋めて Artifact を作成すること：

```markdown
# [設計計画] {機能・タスク名}

> [!NOTE]
> **目的**: {解決する課題を1文で記述}
> **達成基準**: {何ができれば完了とするかを1〜2行で記述}

---

## 1. 意思決定とトレードオフ

### 決定 1: {論点名}
- **採用方針**: {採用する方式}
- **採用理由**: {選定理由・メリット}
- **見送った案**: {代替案と、それを却下した理由}

### 決定 2: {論点名}
- **採用方針**: {採用する方式}
- **採用理由**: {選定理由・メリット}
- **見送った案**: {代替案と、それを却下した理由}

---

## 2. システム境界と責務

> [!TIP]
> **責務の分担方針**: {全体の分離ルールや依存の方向性を1文で記述}

### 対象領域（やること）
- **{論理モジュールA}**: {果たすべき責務}
- **{論理モジュールB}**: {果たすべき責務}

### スコープ外（今回あえてやらないこと）
- {やらないこと・次回以降に回すこと}

---

## 3. 振る舞いの変化

### 【通常時】{操作・トリガー名}
- **従来の挙動**: {以前の状態・結果}
- **新しい設計**: {設計後の状態・結果}

### 【異常系】{エラー・境界条件}
- **従来の挙動**: {以前の状態・結果}
- **新しい設計**: {設計後の状態・結果}

---

## 4. ユーザー判断が必要な事項

> [!IMPORTANT]
> **以下の判断について回答・選択してください。未決定のまま実装には進みません。**
> 
> 1. **{論点1のタイトル}**
>    - **選択肢A (推奨)**: {内容とメリット}
>    - **選択肢B**: {内容と懸念点}
> 
> 2. **{論点2のタイトル}**
>    - {判断・合意が必要な内容}
```

---

## 4. チャット出力フォーマット（引き継ぎプロンプト付き）

Plan Artifact を生成・提示する際、チャットへの最終出力には **「別コンテキストへそのままコピペして実装を開始できる引き継ぎ用コードブロック」** を必ず添付すること。

### チャット出力テンプレート

```markdown
📝 **[PLAN ARTIFACT CREATED]**
設計計画（Artifact）を作成しました。内容を確認し、問題がなければ以下のプロンプトをコピーして **新しいセッション（コンテキスト）** で実行してください。

- **Plan Artifact**: [plan.md](file:///<appDataDir>/brain/<conversation-id>/plan.md)

---

### 📋 次コンテキスト引き継ぎ用プロンプト（ワンクリックコピー）

\`\`\`markdown
以下の確定した Plan Artifact に基づいて、Planner を起動し、タスクファイル（tasks/TASK-*.md）の作成から実装・検証（Worker / Reviewer 連携）まで完遂させてください。

- **Plan Artifact パス**: <appDataDir>/brain/<conversation-id>/plan.md
- **決定事項の回答**:
  - 論点1: 選択肢A（推奨）
  - 論点2: 選択肢A（推奨）
\`\`\`
```
