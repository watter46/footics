# Knowledge Management Rules (KI 管理規約)

**Activation:** This rule is **ALWAYS ON** for all tasks and workflows.

> **Positioning:** 本プロジェクトにおける「仕様と実装の乖離」を防ぎ、AIが常に最新のコンテキスト（Knowledge Items: KI）に基づき自律的に行動するための運用ルールです。

## 1. 知識の単一情報源 (Single Source of Truth)
- **原則:** すべての重要な設計判断、アーキテクチャ仕様、および規約はリポジトリ内の `.agents/knowledge/` 配下で管理されます。
- **行動指針:**
    - AIは、タスクに着手する前に必ず関連するKIが存在しないかを確認（Index Before Act）しなければなりません。
    - 古い知識や外部の不確定な情報に頼らず、`.agents/knowledge/` の内容を最優先の真実として扱います。

## 2. KI の構成と配置
- **原則:** 知識はトピックごとにディレクトリを切り、原本（仕様）と蒸留知見（AI向け制約）を同居させます。
- **構成:**
    - `.agents/knowledge/[topic-name]/`
        - `spec.md`: （任意）人間が記述した、または詳細な背景を含む仕様書の原本。
        - `content.md`: **（必須）** `spec.md` や実際のコードから「AIが遵守すべき設計制約・プロトコル」を抽出・蒸留した Markdown。箇条書きを多用し、トークン効率と可読性を最大化すること。
        - `metadata.json`: **（必須）** トピックの概要、関連ファイルパス、作成日時、更新日時を含むメタデータ。

## 3. 実装前の参照義務 (Read Protocol)
- **原則:** 推測による実装（Guessing）を禁止します。
- **行動指針:**
    - 新しいタスクの計画 (`/plan`) を立てる際、対象領域に関連する KI を `metadata.json` またはディレクトリ名から検索し、必ず `content.md` を読み込んでから計画を作成してください。

## 4. 自動更新と知見の維持 (Update Protocol)
- **原則:** 仕様の変更に伴うドキュメントの陳腐化を、AI自身の自律的な行動によって防ぎます。
- **行動指針:**
    - タスクの完了時や、設計・仕様に重要な変更を加えた（または発見した）場合、AIは自発的に `/knowledge-update` ワークフローを実行し、関連する KI を更新、または新しい KI を作成しなければなりません。
    - **「重要な変更」の定義**:
        - 新しいライブラリやフレームワーク機能の導入
        - データの保存・同期フローの変更
        - ディレクトリ構造のルール変更
        - 複数ファイルにまたがる新しいデザインパターンの適用

## 5. 蒸留 (Distillation) の品質基準
- **原則:** AIが読みやすく、実行可能な粒度で知見を記述します。
- **行動指針:**
    - 長大な仕様書をそのまま KI にコピペすることは避けてください。
    - 「何をするのか（What）」「なぜそうするのか（Why）」よりも、**「実装において具体的にどの関数/ルールを守るべきか（How/Constraints）」** に重点を置いて抽出してください。
    - 重要な警告や、過去に発生したアンチパターンは `> [!WARNING]` 等の GitHub Alerts を用いて強調してください。
